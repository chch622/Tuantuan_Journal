# ERROR_STATES.md — 错误状态设计

> **错误必须清晰、诚实、可恢复。**
> **不要让错误颜色破坏整体温柔氛围。**

---

## 1. 错误状态原则

- 错误信息必须清晰：用户需要知道发生了什么
- 错误信息必须诚实：不要掩盖问题
- 错误信息必须可恢复：提供下一步操作
- 错误颜色明确但不刺眼

---

## 2. 错误文案

### 2.1 禁止

```
发生未知错误
Error
操作失败
系统异常
```

### 2.2 推荐

| 场景 | 错误信息 | 操作 |
|------|----------|------|
| 照片读取失败 | 这张照片暂时无法读取 | 重试 |
| 保存失败 | 保存遇到了问题，请再试一次 | 重试 |
| 备份失败 | 备份没有完成，请检查存储空间 | 重试 |
| 恢复失败 | 恢复遇到了问题 | 重试 |
| 文件不存在 | 这个文件似乎已经被移走了 | 返回 |
| 存储空间不足 | 存储空间不够了，请清理一些空间 | 管理 |
| 数据损坏 | 这条记录的数据似乎有问题 | 联系支持 |

---

## 3. 错误状态组件

使用 `TtErrorState` 组件：

```
[错误图标]             ← TtIcon, Large, Error 色
[错误标题]             ← TitleMedium, OnSurface
[错误说明]             ← BodyMedium, OnSurfaceVariant
[操作按钮]             ← TtOutlinedButton "重试"
```

---

## 4. 错误展示方式

### 4.1 Snackbar

适用于：轻量级、可恢复的错误

- 底部显示
- Error 色
- 包含操作按钮
- 自动消失（5 秒）

### 4.2 全屏错误

适用于：页面级错误（数据加载失败）

- 使用 `TtErrorState` 组件
- 居中显示
- 包含重试按钮

### 4.3 字段错误

适用于：表单验证错误

- 字段下方显示错误文字
- Error 色
- 输入框边框变 Error 色

### 4.4 Dialog

适用于：严重错误、需要用户确认

- 很少使用
- 仅用于不可恢复的操作警告

---

## 5. 错误颜色

Error 色使用 `TuantuanColors.Error`，明确但不刺眼。

- Light: #BA1A1A（柔和红）
- Dark: #FFB4AB（深色模式下的柔和红）

不要让错误颜色破坏整体温柔氛围。
